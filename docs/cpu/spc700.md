## The core

* Every cycle is one bus call — read, write, or internal — and the dummy
  reads are real reads, because on the S-SMP a read of `$FD`–`$FF` clears a
  timer counter.
* The interpreter is generic over a per-cycle `Bus`, so the S-SMP owns a
  `Core` and steps it over its own decoder; `cpu.spc700` is the standalone
  device over an `AddressSpace`.
* `SLEEP`/`STOP` halt; each halted step is a dummy read of `PC` and an
  internal cycle, which is what the SST traces record.
* The reset sequence is two reads of `$FFFE`/`$FFFF`. How many cycles the
  chip spends before them is not documented by any source here.

## The S-SMP (`snes.apu`)

| Address | Register | Modelled |
| --- | --- | --- |
| `$F0` | TEST | stored; bit 1 (RAM write enable) and bits 0/3 (timer enable/halt) honoured; wait-state bits not modelled |
| `$F1` | CONTROL | timer enables (0→1 resets the stage-2 and output counters), port-latch clears (bits 4/5), IPL ROM enable (bit 7) |
| `$F2`/`$F3` | DSPADDR/DSPDATA | to the `SDsp` seam; reads of `$80`–`$FF` mirror `$00`–`$7F`, writes there are ignored |
| `$F4`–`$F7` | CPUIO0–3 | read: what the S-CPU wrote; write: what the S-CPU reads |
| `$F8`/`$F9` | AUXIO | plain storage |
| `$FA`–`$FC` | T0–T2 targets | write-only; `$00` means 256 |
| `$FD`–`$FF` | T0–T2 outputs | 4-bit, cleared by a read (not by a debug read) |

T0/T1 tick at 8 kHz (every 128 SMP cycles), T2 at 64 kHz (every 16). Writes to
`$F0`–`$FF` also land in the RAM underneath, and writes to `$FFC0`–`$FFFF`
always go to RAM whether or not the IPL ROM is mapped.

### The IPL ROM is a clean-room replacement

Nintendo's 64-byte boot ROM is copyrighted code and is **not shipped**. The
device's default IPL is our own SPC700 program, written from the *protocol*
(SNESdev's *Booting the SPC700*), not from a disassembly of Nintendo's ROM; it
is listed byte by byte, with every line commented, in `src/dev/snes/apu.rs`.
It sets `SP=$EF`, clears `$01`–`$EF`, posts `$AA`/`$BB`, waits for `$CC`, and
then implements the block-transfer handshake: data in port 1, index in port 0,
echo, a kick of any other value ends the block, command 0 jumps.

A real dump may be supplied through the optional `ipl` media property (exactly
64 bytes). Software that reads the ROM's bytes, or jumps into the middle of it
— rare, but it happens — needs the real one.

The S-CPU side is the `cpuio` region (64 bytes, `$2140`–`$217F`, the four
ports mirrored).
