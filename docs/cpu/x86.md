# x86 / x86-64

Consumed by: `cpu/x86`. The largest and most treacherous ISA rsemu
targets — variable-length decode, segmentation, four operating modes,
self-modifying code, and decades of accumulated corner cases.

## Implementation notes

- **Decode is the hard part**, not execution: prefixes (including the REX/VEX/EVEX
  families), ModRM/SIB, and instruction-length limits. Build the decoder from
  the SDM opcode maps and sandpile's tables, and generate it from a declarative
  description rather than hand-writing it twice.
- **Self-modifying code is mandatory**, not optional — real DOS and Windows
  software relies on it. This is why the JIT needs page-level dirty tracking
  (`ROADMAP.md` §9).
- **x86 is TSO.** On a weakly-ordered host (AArch64, wasm), the frontend lifter
  must insert barriers; see [`../techniques/memory-models.md`](../techniques/memory-models.md).
- Segmentation is not vestigial in the modes we must support. Real mode,
  protected mode with a full descriptor cache, `v8086`, compatibility mode and
  long mode all have to coexist.

## What `cpu/x86` implements today

One interpreter, five parts, chosen by a `Variant` construction property:
8086, 8088, 80386, 80486 and a generic x86-64. Real mode on all five;
protected mode, paging, privilege levels, gates, task switching and the
exception model on the 32-bit ones; `CPUID` and the other 486 additions on the
486; long mode, `REX`, the sixteen 64-bit registers and four-level paging on
the last. Gated against `SingleStepTests/8088` twice — as the 8088 it was
captured from, and as a 386, where every disagreement is traced to a
documented difference between the parts.

**A second processor can be started by the first.** `INIT` — a pin, or a
message from this core's own local interrupt controller through
`core::wire::LocalController` — is a *lesser* restart than `RESET`: it leaves
the processor in the wait-for-SIPI state rather than fetching from the reset
vector, and nothing but a Start-Up moves it from there, not an `INTR` and not an
`NMI`. A Start-Up names a page and the processor begins at
`CS:IP = page << 8 : 0`. That is the MultiProcessor Specification's universal
startup algorithm (§B.4), and `tests/pc_apic_smp.rs` drives it with a *guest*
executing the three interrupt-command-register writes.

**The model-specific registers** are a short list, and an address that is not on
it raises `#GP(0)` rather than reading as zero: `IA32_EFER`, the four `SYSCALL`
registers, the three segment-base registers, the time-stamp counter that
`RDTSC` also reads, `IA32_MISC_ENABLE`, the twenty memory-type range registers,
and `IA32_APIC_BASE` — the one whose state is not in the
processor at all, and which reaches the local controller through the same peer
link the INIT does. Its base-address *field* is reported and not obeyed:
relocating the register window is an address-space retopology, and a machine
file's `map` places the page.

The **memory-type range registers** are reported and not obeyed either, for a
different and stronger reason: a memory type says what a *cache* may do, and
this core has none — every access is one bus transaction in program order,
which satisfies `UC`, and `UC` is a legal implementation of every weaker type.
So `IA32_MTRRCAP`, `IA32_MTRR_DEF_TYPE`, the eight variable base/mask pairs and
the eleven fixed ranges are architectural state that round-trips a snapshot,
with the reserved bits and the two undefined types refused the way hardware
refuses them, and no guest can tell the answer from a processor with its caches
off. They are gated on `Features::mtrr`, which every long-mode part has —
`Features::validate` says so — because a 64-bit Linux without them reports
`MTRRs disabled (not available)` and then refuses every 2 MiB mapping.

**Floating point is software throughout.** The x87 unit (the eight-register
rotating stack, the tag word, precision and rounding control, the condition
codes, the six exception masks and the deferred `#MF`) and SSE/SSE2 (sixteen
`XMM` registers, `MXCSR`, the scalar and packed arithmetic, SSE2's whole
packed-**integer** half, `FXSAVE`) both go
through [`src/float`](../../src/float), which has no host `f32` or `f64` in it
at all. That is what `ROADMAP.md` §9.1 asks for and the reason two hosts agree
bit for bit. Which of them an instance *has* is `Features`, not `Variant`: a
486SX is a 486 with `fpu` clear, and `CPUID` follows the features.

**The reciprocal approximations are correctly rounded.** `RCPPS`, `RCPSS`,
`RSQRTPS` and `RSQRTSS` are specified by an error *bound* — a relative error of
at most `1.5 × 2^-12` — rather than by a result, and real parts disagree in the
low bits, so there is no one part's answer to reproduce. This core returns the
correctly rounded `1/x` and `1/sqrt(x)` in single precision, to nearest: that
is inside the bound on every input, it is bit-reproducible on every host
because it is software (`RCP` is `float`'s division; `RSQRT` is exact integer
arithmetic in `fpexec`, rounded once, because a rounded root followed by a
rounded division is two roundings), and it is what a Newton refinement step
converges on anyway. A guest that compares against values recorded on
particular silicon will see different low bits. The special cases are the
manual's: `MXCSR.RC` is ignored, a denormal operand is a zero of its sign and
a tiny result is a zero whatever `DAZ` and `FTZ` say, `±0` gives `±inf`,
`+inf` gives `+0`, a negative operand to `RSQRT` gives the QNaN indefinite, a
NaN comes back quiet, and no `MXCSR` flag is ever raised — these instructions
have no SIMD floating-point exceptions at all.

**MMX is the x87 unit seen another way.** There is no MMX register file: `MMn`
is the 64-bit significand of x87 *physical* register `Rn` (*Intel SDM* Vol 1
§9.5), and `fpu::X87::mm` reads exactly that. The aliasing carries the
architecture's side effects, because operating systems and mixed x87/MMX code
lean on them: every MMX instruction except `EMMS` sets `TOP` to 0 and the
whole tag word to valid before it runs, so `MMn` and `ST(n)` coincide and an
x87 instruction that follows finds a full stack; a write to `MMn` sets bits
79:64 of `Rn` to all ones, so x87 code reading an MMX result sees a NaN or an
infinity rather than a plausible number; and `EMMS` marks every register
empty. Because nothing lives anywhere else, `FSAVE`/`FRSTOR`,
`FXSAVE`/`FXRSTOR` and the core's own snapshot carry the MMX state with no code
that knows it exists. The gates are the MMX exception tables', not SSE's:
`CR0.EM` is `#UD`, `CR0.TS` is `#NM`, a pending x87 exception is `#MF` before
the instruction, and only the forms that also name an `XMM` register
(`MOVQ2DQ`, `MOVDQ2Q`, the `CVT*PI*` conversions) need `CR4.OSFXSR`. The whole
integer set is here on `Features::mmx` (`CPUID.01H:EDX[23]`); SSE's additions on
`MM` registers (`PAVGB`/`PAVGW`, `PMINUB`/`PMAXUB`, `PMINSW`/`PMAXSW`,
`PSADBW`, `PSHUFW`, `PEXTRW`/`PINSRW`, `PMOVMSKB`, `PMULHUW`, `MASKMOVQ`,
`MOVNTQ`, `CVTPI2PS`/`CVTPS2PI`/`CVTTPS2PI`) also need `sse`, and SSE2's
(`PADDQ`, `PSUBQ`, `PMULUDQ`, `MOVQ2DQ`, `MOVDQ2Q`,
`CVTPI2PD`/`CVTPD2PI`/`CVTTPD2PI`) `sse2`. A conversion that reads its
doublewords from memory (`CVTPI2PS xmm, m64`) names no `MM` register and makes
no transition. In the opcode tables an MMX row is the SSE2 operation with `MM`
operands — `0F FC` and `66 0F FC` are both `PADDB` — and the lane arithmetic is
shared, so the two register files cannot disagree about a lane.

**The x87 transcendentals are correctly rounded too.** `F2XM1`, `FYL2X`,
`FYL2XP1`, `FPTAN`, `FPATAN`, `FSIN`, `FCOS` and `FSINCOS` are specified by an
accuracy bound (*Intel SDM* Vol 1 §8.3.10: under one ulp to nearest from the
Pentium on), and parts differ in the last bit. This core returns the exact
mathematical result rounded once to 64 bits under `RC` — inside the bound on
every part, and a function of the operands alone, so every host agrees.
[`float::elementary`](../../src/float/elementary.rs) does it with Ziv's
strategy: an enclosure of the true value in multi-precision fixed point whose
error bound is carried exactly through every operation, widened from 128 bits
until both ends of the enclosure round the same way. Results that sit near a
representable number *by construction* (`sin x` for tiny `x`, `cos x` near 1,
`atan(y/x)` for tiny `y/x`, `2^x - 1` near −1) are settled in closed form
instead. `π` and `ln 2` are computed to the precision each attempt needs
(Machin, `2 atanh(1/3)`), so the trigonometric reduction is exact for every
argument — which is **more** accurate than silicon: Intel reduces against a
66-bit `π`, so for a large argument near a multiple of `π` a real `FSIN`
returns a correct rounding of `sin(x · π / π₆₆)` rather than of `sin x`. The
architectural behaviour is exact: `|x| ≥ 2^63` sets `C2` and leaves the
operand alone, `FPTAN` pushes `1.0`, `FSINCOS` leaves the cosine on top, `C1`
reports the rounding direction (the one place it does), precision control
does not apply (§8.1.5.2's list is closed), and the special-operand tables,
`#IA`/`#Z`/`#D`/`#U`/`#O`/`#P` and the stack faults follow each instruction's
page. Outside their documented domains, where the manual says "undefined",
`F2XM1` and `FYL2XP1` return the correctly rounded mathematical value. The
reference values in the tests come from mpmath, run as a black box at 4000
and 6000 bits. `FBLD`/`FBSTP` (18-digit packed decimal, the decimal
indefinite on overflow or a NaN) are exact.

**The XSAVE feature set** is on `Features::xsave` (machine-file property
`xsave`), which no preset has yet — the AMD64 baseline predates it, and AVX
will bring it in. It is `XCR0` (reset value 1, snapshotted) with
`XGETBV`/`XSETBV`, `CR4.OSXSAVE` (a `#GP` to set on a part without the
feature) echoed live in `CPUID.01H:ECX[27]`, `CPUID` leaf `0Dh`, and `XSAVE`,
`XSAVEOPT`, `XSAVEC` and `XRSTOR` with their `REX.W` forms (*Intel SDM* Vol 1
ch. 13). The legacy region is written by the same code as `FXSAVE`, so the
two images agree byte for byte — except that outside 64-bit mode the SSE
component is `XMM0`-`XMM7` only (§13.5.2), where `FXSAVE` writes all sixteen.
Three choices the manual leaves open: **`XINUSE` is exact** — a component is
in use exactly when it differs from its init configuration (`MXCSR` excluded,
§13.6), computed at each save rather than tracked, and reported by `XGETBV`
with `ECX = 1`; **`XSAVEOPT` is `XSAVE`** — its modified optimisation is a
permission, and skipping it changes only bytes the architecture calls
unspecified; and **`XSAVEC` is implemented** (with `XRSTOR`'s compacted form)
because with no supervisor components it costs a few lines. When the maximum basic
leaf rises to `0Dh` the leaves between answer zero, which on each of them is
the "nothing here" answer (leaf 2 returns the architectural `AL = 01h` with
null descriptors; leaf `0Bh`'s `EBX = 0` is the SDM's own "not supported").

**The extensions past SSE2 are each one `Features` bit and one `CPUID` bit.**
SSE3 (`Features::sse3`, `CPUID.01H:ECX[0]`) is the horizontal and alternating
arithmetic (`HADDPS`/`HADDPD`, `HSUBPS`/`HSUBPD`, `ADDSUBPS`/`ADDSUBPD`), the
duplicating loads (`MOVDDUP`, `MOVSLDUP`, `MOVSHDUP`), `LDDQU` and `FISTTP`;
each lane is a `float` operation under `MXCSR`, and an unmasked exception in
any lane leaves the destination alone, as SSE's own do. A part without the bit
raises `#UD` for every one of them, ahead of the `CR0`/`CR4` gates they
otherwise share with SSE. `MONITOR` and `MWAIT` are not here: they raise
`#UD`, and the bit that announces them (`CPUID.01H:ECX[3]`) stays clear, which
is what a guest checks before using them. SSSE3 (`ssse3`, `ECX[9]`) is
`PSHUFB`, `PALIGNR`, the horizontal integer adds and subtracts, `PMADDUBSW`,
`PMULHRSW`, `PSIGN*` and `PABS*`, each in two forms: on `XMM` registers
behind a `66`, and bare on `MM` registers with MMX's gates and its x87
transition — the last extension to have `MM` forms at all. The two forms share
one lane kernel, parameterised by width, because `PSHUFB`'s index, `PALIGNR`'s
concatenation and the horizontal forms' halves are not the low half of the
128-bit answer. SSE4.1 (`sse41`, `ECX[19]`) is the rest of the packed-integer
gaps (`PMINSB`…`PMAXUD`, `PMULLD`, `PMULDQ`, `PCMPEQQ`, `PACKUSDW`, the twelve
`PMOVSX`/`PMOVZX` widenings, which read exactly the bytes they widen), the
blends — the variable ones take their mask from `XMM0`, which the tables carry
as an operand so the disassembler shows it — `PTEST`, `PHMINPOSUW`,
`MPSADBW`, the byte/doubleword extracts and inserts and `EXTRACTPS`/`INSERTPS`
(a general-register destination is written whole, zero-extended), the
`MOVNTDQA` aligned load, and the floating-point `ROUND*` and `DPPS`/`DPPD`. The
rounds take their direction from `imm[1:0]` or, with `imm[2]`, from
`MXCSR.RC`; `imm[3]` suppresses the precision exception; they raise invalid
only for a signalling NaN and never the denormal-operand exception, while
`DAZ` still applies. The dot products multiply only the lanes `imm[7:4]`
selects and sum in the manual's order, `(p0 + p1) + (p2 + p3)`, each step
rounded. SSE4.2 (`sse42`, `ECX[20]`) is `PCMPGTQ`, the four string compares
and `CRC32`. The string compares implement the whole immediate (*Intel SDM*
Vol 2 §4.1): byte or word, signed or unsigned elements; the four aggregations
— equal any, ranges, equal each, equal ordered — with the valid/invalid
override table that makes them string operations rather than register ones,
including equal ordered's partial match at the end of the register; the four
polarities; the least- or most-significant index into `ECX` or the bit or
element mask into `XMM0`; and their own flag definitions (`CF` result
non-zero, `ZF`/`SF` either string ending inside its register, `OF` result
bit 0). Explicit lengths are the absolute values of `EAX`/`EDX`, or of
`RAX`/`RDX` with `REX.W`, saturated. `CRC32` is CRC-32C (the Castagnoli
polynomial `0x1EDC6F41`, reflected), in byte, word, doubleword and quadword
forms, and is gated by its `CPUID` bit alone — it touches no SIMD state, so
`CR0.EM`, `CR0.TS` and `CR4.OSFXSR` mean nothing to it. `POPCNT` (`popcnt`,
`ECX[23]`) arrived beside SSE4.2 with a bit of its own and is gated the same way;
it clears every arithmetic flag but `ZF`, which says the source was zero. The instruction maps behind the
later extensions — `0F 38` and `0F 3A` — are declarative tables like every
other (`isa::decode_map`), reached by escape byte today and by a VEX prefix's
map number when there is a VEX decoder.

Known gaps, each deliberate and none silent: no `MONITOR`/`MWAIT`, no
AVX or later, no
`XSAVES`/`XRSTORS` (there are no supervisor state components for `IA32_XSS`
to name); no `FERR#` pin, so an unmasked x87 exception is delivered as `#MF`
only with `CR0.NE` set; **virtual-8086 mode without the extensions** — the mode
itself is here, entered by an `IRET` off a nine-doubleword frame with `VM` set
and left through the protected-mode interrupt table, with the six
`IOPL`-sensitive instructions trapping below `IOPL` 3 and the I/O permission
bitmap consulted whatever `IOPL` says (*Intel SDM* Vol 3A §20.2, §20.3), but
`CR4.VME` and `PVI` are not, so `EFLAGS.VIF` and `VIP` have no storage: they
are storage only where one of those two gives the processor virtual interrupts
to keep, and a guest that found them writable would be told a mechanism exists
behind them (Vol 1 §3.4.3.3). `EFLAGS.ID` **is** storage, on every part whose `Features` include
`CPUID`, because that flag's only function is to announce the instruction and a
guest that cannot set it concludes the part predates it — which cost
`q35-linux-smp` its second processor for as long as nobody had run a sixteen-bit
startup path; no *architectural* debug breakpoints (`DR0`–`DR7`
round-trip and nothing fires — the host's own breakpoints, below, are a
different mechanism and do fire); no alignment check; `LOCK` held as a **bus
lock** across the instruction, so a locked read-modify-write is indivisible
against another core's *locked* access but not against its plain store
(`core::space::BusLock` says where the line is and why); the invalid-opcode
exception a `LOCK` on a non-lockable instruction should raise is still not
enforced; the accessed bit set on `MOV Sreg` and far transfers but not on the
segment loads a gate or a task switch performs; no 286-format task state
segment (`#TS` rather than a truncated switch); and no A20 gate — that one is
chipset, not CPU.

## Exits to the host

`X86` implements `core::exec::ExitingCore`, the level-3 seam the AArch64,
RISC-V and MIPS cores and `accel::kvm` already had: a host that runs a
user-mode guest — a Win16 or Win32 personality, a Linux system-call layer, a
test harness — gets control back at the events it services instead of having
them delivered through a guest interrupt table it never built. The consumer
that asked for it is [univdreams](https://github.com/KarpelesLab/univdreams)
(issues #35 and #36).

Four reasons, each named in the mask (`set_exit_mask`); with an empty mask, no
system-call vectors and no breakpoints armed the core is the one it was before
— `Exec` is not even handed the configuration, so the cost is one test of a
`None` per instruction.

| Reason | Raised by | Core `RIP` afterwards | `Exit` |
| --- | --- | --- | --- |
| `SYSCALL` | `SYSCALL`, `SYSENTER`, `INT n` for a vector in `set_syscall_vectors`, a taken `INTO` if 4 is in the set | **past** the instruction | `pc` the instruction, `len` its length |
| `FAULT` | any exception an instruction raises: `#UD`, `#GP`, `#PF`, `#DE`, `#SS`, `#NP`, `#BR`, `#MF`, … | **at** the instruction, register file as it found it | `detail` = `FaultDetail` (vector, error code); `#PF` adds `address` and `access` |
| `HALT` | `HLT` at a privilege that may execute it; a core already halted | **past** the `HLT`, *not* halted | `pc` the resume point, `len` 0 — `accel::kvm`'s shape |
| `BREAKPOINT` | `INT3`, `ICEBP` | **at** the instruction | `len` 1, so `set_pc(pc + len)` steps over |
| `BREAKPOINT` | a host breakpoint, whatever the mask says | **at** the instruction, nothing fetched or charged | `len` 0, `address` the linear address |

`SHUTDOWN` is also honoured for a triple-faulted core when the mask has it.

**System calls bypass everything about the guest's entry point.** No `LSTAR`,
`STAR`, `IA32_FMASK`, `RCX`, `R11`, `RFLAGS`, `CS` or `SS` change for a
`SYSCALL`; no interrupt-table read, gate privilege check or virtual-8086
`IOPL` check for a selected `INT n`; and the `EFER.SCE` enable is not
consulted, because it asks whether a *guest* kernel set up the entry point the
host is replacing. The decode is still the architecture's: `SYSCALL` outside
64-bit mode is `#UD` and stays one. `SYSENTER` (`0F 34`) is decoded so that it
can exit, and executed architecturally it is the `#UD` of a part without
`SEP`, because its three model-specific registers are not modelled. Which
vectors count is a method rather than a `Config` field because it is the same
kind of thing as the mask — host configuration that changes while the core
lives and that a snapshot does not carry.

**Faults stop at the instruction, never mid-way.** The register file is the
one the faulting instruction started with, so resuming re-executes it — a
demand-paging host maps the page and resumes. A `REP` string instruction keeps
the iterations it completed (`RCX` and the indexes say how far it got, `RIP`
on the prefix), which is the architecture's restart rule (*Intel SDM* vol. 2,
`REP`) and, since this work, also what a *delivered* fault pushes. An 8086's
divide error, which architecturally pushes the address after the divide, also
exits at the divide. `CR2` is **not** written by a `#PF` the host takes —
latching it is part of delivery — and the faulting linear address is in
`Exit::address` instead; `Exit::access` is `Execute` for a fault before the
instruction finished decoding and the error code's write bit otherwise. The
error code itself is packed into `Exit::detail` (bits 0–7 the vector, bit 8
"has an error code", bits 32–63 the code); `FaultDetail::from_detail` unpacks
it, and `detail & 0xff` is the vector on every fault. Faults raised while
delivering an *external* interrupt or `NMI` still go through the double-fault
ladder: those are the guest's interrupt table's problem, not an instruction's.

**Host breakpoints** (`add_breakpoint`, `add_breakpoint_range`,
`remove_breakpoint`, `remove_breakpoint_range`, `clear_breakpoints`) name
**linear** addresses, and fire when an instruction *starts* on one — checked
after the interrupt check, so an interrupt pending at a breakpoint is taken
first and the breakpoint fires when the handler returns to it. Nothing is
written to guest memory and the address need not be mapped, which is what a
thunk window wants: a `CALL` into it stops before any fetch. **Resuming
executes the instruction**: the stop records its address, and the next
instruction to start consumes the record — executing through the breakpoint if
it is at that address, checking normally anywhere else. That is gdb's
step-over without the disarm and re-arm; a host that moved `RIP` first gets no
exemption, and an interrupt delivered before the instruction does not use it
up, because delivery starts no instruction.

**Every engine stops on the same instruction.** Under `jit` and `jit-host`
every exit but a fault comes from an instruction outside the lifted subset, so
the interpreter raises it; a fault inside a translated block leaves through the
same `Exec::fault_exit`, with the length read off the block's open boundary.
For breakpoints, arming or disarming flushes the translation cache, the lifter
reads no byte at an armed address — so no block contains an instruction that
starts on (or straddles) one — and a block entry on an armed address is handed
to the interpreter. The host-breakpoint tests run on every engine, including a
breakpoint armed in the middle of a loop that is already running translated.

**`DR0`–`DR7` still do not fire.** The comparison is the same one, but an
architectural `#DB` needs `DR6` status, `DR7` enables per privilege level,
`RF` suppression on return, and data breakpoints to be honest, and none of that
falls out of a host-side list. It is left as the documented gap it was.

Exits are reported by `step_to_exit`, `run_to_exit_ticks` and
`ExitingCore::run_to_exit`. `step`, `run` and `run_budget` — the machine
scheduler's path — drop an exit and leave the core at its resume point, the
same as the AArch64 core does.

## ⚠ Do not consult

Bochs (LGPL), DOSBox (GPL), and QEMU (GPLv2) are the three sources people reach
for when x86 gets difficult. All three are forbidden. The SDM answers the
question — it is just longer.
