# WDC 65C816

The 16-bit member of the 6502 family: the CPU of the SNES (inside Ricoh's
5A22) and the Apple IIGS. Implemented as its own core, `cpu::w65c816`
(feature `cpu-w65c816`, device class `cpu.w65c816`), not as a variant of
`cpu::mos6502` — see the module docs for why.

Consumed by: `cpu/w65c816`.

## Implementation notes

- **Every cycle is a read, a write or an internal operation**, made through
  `Exec::cycle` in the order table 5-7 lists, with the address the datasheet
  says is driven — internal operations included.
- **Timing belongs to the board.** Each cycle is priced by an optional
  `AccessTiming` provider, published by another device as
  `ExportId::ACCESS_TIMING` (16) in a `TimingPort`, and named by the core's
  `timing` property. It is called once per cycle, before the access, with a
  `BusCycle { addr, pins, data }`; `pins` carries VDA, VPA, VPB, RWB, E, M, X
  and MLB, plus `HELD` for a cycle `/RDY` is holding. It returns clocks of the
  core's domain (zero is treated as one). With no provider every cycle is one
  clock. On a SNES the core runs in the master-clock domain and the board
  answers 6, 8 or 12.
- **`/RDY`** is the `CycleGate` export (`rdy` property), as on the 6502. The
  gate is consulted after every cycle, writes included — RDY on the W65C816S
  stretches any cycle. A held or stolen cycle charges clocks (priced through
  the timing hook with `HELD`) but is not a bus cycle.
- **Open bus.** A refused or undriven read returns the last value on the data
  bus — the SNES's MDR — and `bus_faults()` counts the refusals.
- **Emulation-mode quirks**, as the corpus pins them: the 6502-era stack
  instructions wrap in page one, while `PEA`, `PEI`, `PER`, `PHD`, `PLD`,
  `PLB`, `JSL`, `RTL` and `JSR (a,X)` run the 16-bit stack pointer and restore
  `SH = $01` afterwards; with `DL = 0` the direct page wraps like page zero
  for `d,X`, `d,Y`, `(d)`, `(d,X)` and `(d),Y`, but not for `[d]`, `[d],Y` or
  `PEI`; a read-modify-write's modify cycle is a write of the old value with
  VDA and VPA low (nothing selected), where native mode spends an internal
  operation.
- **Status changes and the MX pins.** `RTI` pulls P first but its new M and X
  appear on the pins only after the PC (and PBR) pulls.
- **`WDM`** is two bytes, but its second cycle is an internal operation: the
  signature byte is never fetched.
- **ABORT** is edge-sensitive. The aborted instruction runs all its bus
  cycles; its register changes are undone, and the ABORT vector is taken with
  the aborted opcode's address pushed. Memory writes it made stand.
- **`WAI`** wakes on IRQ even with I set (continuing after the `WAI`), on NMI,
  and on ABORT; **`STP`** stops until reset.
- **Reset** leaves the stack pointer's low byte as it was (table 2-2 lists it
  as not initialised); everything else follows table 2-2.

## Validation

[SingleStepTests/65816](https://github.com/SingleStepTests/65816) — MIT,
© Thomas Harte et al. — 512 files, every opcode in both modes, 10 000 vectors
each (100 for `MVN`/`MVP`, whose vectors cover a whole move), with the full bus
trace and the pin states of every cycle. Fetched at a pinned commit by
`scripts/fetch-testdata.sh sst-65816` (2.7 GB) and run by
`tests/conformance/sst65816.rs`:

```text
scripts/fetch-testdata.sh sst-65816
RSEMU_CONFORMANCE=1 cargo test --release --test conformance sst_65816 -- --nocapture
```

**All 5 080 400 vectors pass** — registers, memory, cycle count, addresses,
data and pins on every cycle — so `tests/conformance/ledgers/sst-65816.txt` is
empty. The corpus does not cover interrupts, reset, `/RDY` or the timing
hook; `src/cpu/w65c816/tests.rs` does.
