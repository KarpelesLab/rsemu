# Zilog Z80, Sharp SM83, Intel 8080

Consumed by: `cpu/z80` (Master System), `cpu/sm83` (Game Boy).

## Z80 — primary

| Source | Covers | Notes |
| --- | --- | --- |
| [Zilog UM0080 — Z80 CPU User Manual](https://www.zilog.com/docs/z80/um0080.pdf) | The manufacturer's manual: every documented instruction, flags, timing, interrupt modes 0/1/2 | Start here |
| [Z80 reference (World of Spectrum)](https://worldofspectrum.org/faq/reference/z80reference.htm) | Consolidated opcode tables incl. the undocumented `IX`/`IY` halves and `SLL` | |
| [clrhome opcode table](https://clrhome.org/table/) | Fast visual opcode matrix for cross-checking a decoder | |

The **`MEMPTR`/`WZ` internal register** and the `F` register's undocumented bits
3 and 5 are observable through `BIT n,(HL)` and `SCF`/`CCF`. They are required
to pass the standard test suites, so model them from the start rather than
retrofitting.

## SM83 (Game Boy) — primary

The Game Boy CPU is **not a Z80** and not an 8080: it drops `IX`/`IY`, the
alternate register set, and the block instructions, and adds `LDH`, `LD (HL±)`
and a different `DAA`.

| Source | Covers |
| --- | --- |
| [Pan Docs](https://gbdev.io/pandocs/) | The reference for the whole machine, CPU included. **CC0** — quotable without restriction |
| [gbdev opcode tables](https://gbdev.io/gb-opcodes/optables/) | Full opcode matrix with cycles and flags |
| [Game Boy: Complete Technical Reference](https://gekkio.fi/files/gb-docs/gbctr.pdf) (Gekkio) | Hardware-measured timing at sub-instruction granularity — the source for M-cycle exact behaviour |

## Intel 8080

Covered by the Z80 material above (the Z80 is a superset); bitsavers carries the
original Intel 8080 manuals when the exact 8080 flag behaviour matters — `DAA`
and the parity flag differ from the Z80 in ways emulator authors get wrong.
